## 🤔 Step 2: Understand Documents (10 minutes)

### What's Different About MongoDB?

**Traditional Database (Like Excel/SQL):**
```
customers table          orders table
+----+------+-----+      +----+----------+------+
| id | name | age |      | id | customer | date |
+----+------+-----+      +----+----------+------+
| 1  | John | 30  |      | 1  | 1        | ... |
+----+------+-----+      +----+----------+------+
                ↑                  ↑
                └──────────────────┘
            (Need JOIN to connect them!)
```

**MongoDB (Like JSON):**
```json
{
  "_id": "1",
  "name": "John Doe",
  "age": 30,
  "orders": [
    { "date": "2024-01-15", "total": 99.99 }
  ]
}
```

**Key Difference:** Related data lives together! ✨

### Why This Matters

**SQL Way:**
1. Query customers table
2. Query orders table  
3. JOIN them in your application
4. **Total: 3 steps**

**MongoDB Way:**
1. Query customer (includes orders)
2. **Total: 1 step** 🚀

**Result:** Faster queries, simpler code!

---

## 💡 The Big Idea: "Data Together"

> ### MongoDB's Golden Rule:
> **"Data that is accessed together should be stored together."**

**Example: An E-commerce Order**

When you view an order, you ALWAYS need:
- ✅ Customer name
- ✅ Items in the order
- ✅ Total price

You RARELY need:
- ❌ Customer's full address
- ❌ Customer's email
- ❌ Product inventory count

**MongoDB Answer:** Store what you need together!

```json
{
  "_id": "order123",
  "customerName": "John Doe",        ← Always needed
  "items": [                         ← Always needed
    { "name": "Laptop", "price": 1299 }
  ],
  "total": 1299,                     ← Always needed
  "customerId": "cust456"            ← Link for rare full lookups
}
```

**Benefits:**
- 🚀 One query gets everything
- 💨 No joins = faster
- 📝 Code is simpler

### Query 3: Create an Order

Let's create an order with **embedded items** (MongoDB's superpower!):

```bash
# First, get your customer ID
CUSTOMER_ID="<paste your customer id here>"

# Create an order
curl -X POST http://localhost:8080/orders \
  -H "Content-Type: application/json" \
  -d '{
    "customerId": "'$CUSTOMER_ID'",
    "customerName": "Jane Smith",
    "items": [
      {
        "productId": "prod123",
        "name": "MacBook Pro",
        "price": 2499.00,
        "quantity": 1
      }
    ]
  }'
```

**Now view it in Compass:**
1. Refresh `orders` collection
2. Click on your order
3. **Notice:** The `items` array is INSIDE the order document!

**This is embedding!** No separate table needed! 🎯

## ❓ Common Questions

**Q: How is this different from MySQL?**
A: MongoDB stores JSON-like documents. Related data can be embedded together, making queries faster (no joins!).

**Q: When should I embed vs reference?**
A: Embed when data is ALWAYS accessed together. Reference when accessed separately. See [SCHEMA_PATTERNS_GUIDE.md](SCHEMA_PATTERNS_GUIDE.md).

**Q: Is MongoDB slower than SQL?**
A: For this use case (orders with items), MongoDB is **100-200x faster** because no joins needed!

**Q: Can MongoDB do transactions?**
A: Yes! This demo shows ACID transactions for inventory management. See [TRANSACTIONS_GUIDE.md](TRANSACTIONS_GUIDE.md).

**Q: What about data consistency?**
A: MongoDB supports ACID transactions, write concerns, and read concerns for strong consistency.
